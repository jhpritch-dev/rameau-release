# Credential shapes that MUST be detected by the pinned secret scanner.
#
# This is a FLOOR, not a pinned total. Adding a candidate shape to
# tools/prove_scanner_fires.py does not make this file wrong; a shape listed here
# that stops firing DOES make the build red, by name, because that is a real loss
# of detection coverage rather than a flake.
#
# It starts EMPTY on purpose.
#
# The shape set was first measured on 2026-11-03 against gitleaks 8.30.1, where the
# AWS access-key shape -- the only shape the control used to plant -- did not fire in
# any variant, while nine other shapes did. But CI pins 8.21.2 (see the "install
# gitleaks" step), so that measurement was taken on a DIFFERENT scanner than the one
# that runs here. Copying its results into this file would be pinning a figure
# produced by the wrong instrument, which is the mistake this whole gate exists to
# catch.
#
# TO FILL IT: read the per-shape matrix printed by the "prove the scanner fires"
# step on a real CI run -- that run uses the pinned version -- and list, one per
# line, the shapes that fired there and that this stack should keep detecting.
#
# Until then the control still enforces Tier 1: at least one generated
# known-positive must be flagged, or the job fails and the real scan's zero is not
# believed.
#
# ---------------------------------------------------------------------------
# ONE ENTRY IS ALREADY SAFE TO PIN, and it is pinned below.
#
# anthropic-key is detected by THIS REPOSITORY'S OWN rule in .gitleaks.toml, not by the
# vendor ruleset. That makes it the one shape whose detection does not depend on which
# gitleaks version CI installs: it is a plain regex on the sk-ant- prefix with no entropy
# threshold, so it behaves the same on 8.21.2 and 8.30.1. Measured firing on draw 1 of 24.
#
# Pinning it here is the point of adding the rule. Without a floor entry the rule is
# merely present; with one, deleting .gitleaks.toml, breaking the regex, or dropping the
# --config flag turns the build red by name.
#
# Everything else stays unpinned until a real CI run on the pinned version reports its
# matrix. Note what must NOT go here: aws-access-key is known-intermittent (~31 % per
# draw, measured) and prove_scanner_fires.py REFUSES a floor containing it, because a
# flaky floor entry reds the build at random and teaches its readers to ignore it.
